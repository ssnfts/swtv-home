# Website Tiles Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement each task with independent review before the next. Steps use checkbox syntax for tracking.

**Goal:** Add private website favorites, confirmed URL sharing and a remote-usable
app-like WebView window to the unpublished SWTV 0.4.0 Cyberpunk release.

**Architecture:** Keep the six-library graph. The app owns URL policy, private
website storage, editing and browser Activities. Launcher-ui receives display-only
site entries and callbacks, never browser cookies or unvalidated addresses.

**Tech Stack:** Existing Kotlin/Android Views/Android WebView on API 29+, JDK17,
compile/target35, Gradle8.9. No new production library; the existing repository's
org.json:json:20240303 test artifact may be reused in app unit tests.

## Global Constraints

- Keep app.swtv.home, six libraries, production signing identity and 0.4.0/code4.
- Google TV stays default HOME and the default Internet browser is not changed.
- No automatic QJY bookmark synchronization, private-browser data access, root or accessibility service.
- Existing launcher schema-1 settings, app dock, OwnTV and HDMI behavior remain compatible.
- Website store is separate and versioned; at most32 entries, title at most100 characters, URL at most2048 characters.
- HTTPS only in the embedded viewer; reject invalid schemes, credentials and malformed addresses. A bare hostname defaults to HTTPS.
- Confirm incoming shared title/address before any save or navigation. Never auto-open or auto-save an external share.
- Preserve significant URL paths, queries and fragments; deduplicate normalized addresses and keep stable IDs/order.
- Use one WebView only while a web page is open; destroy on close and handle renderer failure safely.
- No native JavaScript bridge, file/content URL access, SSL bypass, mixed content, automatic popups/downloads or custom streaming/downloader implementation.
- JavaScript and ordinary first-party site storage may be enabled; QJY sessions/cookies are not copied.
- Web tiles fetch no favicons or site content at launcher startup.
- Use the approved HUD tokens and shared dialogs; respect reduced motion and D-pad focus.
- Network ADB remains closed. Physical delivery uses the installed production app's HTTPS updater and Android confirmation.
- Do not hardcode the user's representative site in product defaults or public release notes.

## Task W1: URL, favorite collection and private storage

**Files:** create focused app/web domain files `WebsiteUrl.kt`,
`WebsiteFavorites.kt`, `WebsiteCodec.kt`, `WebsiteStore.kt`; tests under app/src/test.
Reuse the existing org.json test artifact in app test scope if required.

**Contract for the next task:** provide immutable website records carrying stable
ID, title, normalized URL and derivable display host; a readable snapshot; and
typed mutation results for save/edit/remove/move. Public operations should expose
snapshot(), save(title,address,id?), remove(id), and move(id,delta). Missing ID,
invalid input, capacity, duplicate edit, unreadable data and failed persistence
must be distinguishable. The report records exact API names/types for W2.

- [ ] Read approved spec and current persistence/testing patterns.
- [ ] Add focused failing tests before policy code. Required examples include:
  `bingebang.st -> https://bingebang.st/` as a private test only; scheme/host case
  and default443 dedup; preserved `/?q=a%2Bb#part`; rejected HTTP/javascript/data/
  file/content/intent, user-info, malformed port, control characters, overlength
  input and invalid host. Do not fetch any URL in these tests.
- [ ] Implement a pure normalizer using standard URI/IDN primitives. Normalize
  scheme/host and default port; preserve encoded path/query/fragment. No DNS lookup.
  Reject raw backslashes and ambiguous authorities rather than repairing them.
- [ ] Add pure collection tests for32 limit, stable IDs, duplicate-add no second
  tile, edit conflict, removal, reorder bounds and no unintended neighbor loss.
- [ ] Implement collection operations. Blank title derives from normalized host;
  invalid nonblank titles fail. Existing-ID edits retain the ID and list position.
- [ ] Add codec/storage tests for round-trip order/IDs, missing data, malformed or
  oversized JSON, unknown schema, duplicates and write failure. Never silently
  overwrite an unreadable/unknown-format store while performing an ordinary save.
- [ ] Implement bounded, versioned storage separate from `home/config`. Inject
  a small string-storage boundary so durable mutation logic is JVM-testable, with

receives `WebTile(id,title,host)` and stable open/edit/add callbacks; it does not
normalize or persist URLs. App resolves IDs against the current store before launch.

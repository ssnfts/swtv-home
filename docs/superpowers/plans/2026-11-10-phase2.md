# SWTV Phase 2 Implementation Plan

Goal: deliver the approved native Views launcher and local debug APK, including the user's OwnTV shortcut.

Architecture: app-local Kotlin packages separate pure configuration/catalog logic from Android services and UI. SDK 29 minimum, SDK 35 compile/target, AGP 8.7.3, Kotlin 2.0.21, Gradle 8.9, JDK 17. No JNI, media player, privileged permissions or persistent service. No deployment or HOME/default/settings changes on the physical TV.

Execution: subagent-driven development with a fresh task review after each implementation and a final project review. The root prepares dependencies, runs integration builds and packages deliverables. A new repository on feature/phase2-launcher isolates this work; no worktree is needed because no existing checkout exists.

## Task 1 — Tested configuration and catalog behavior

- [ ] Create core models/configuration codec and tests first. Files: app/src/main/java/app/swtv/home/core/{LauncherConfig,ConfigCodec,CatalogRules}.kt, app/src/test/java/app/swtv/home/core/CoreTest.kt.
- [ ] API: AppEntry(packageName:String, className:String, label:String); ModuleTile(label:String,target:String,kind:String); LauncherConfig(theme:String="auto",accent:String="cyan",columns:Int=6,reducedMotion:Boolean=false,showPhoneApps:Boolean=true,dock:List<String>=emptyList(),hidden:Set<String>=emptySet(),modules:List<ModuleTile>=emptyList(),wallpaperUri:String="",weatherCity:String="",weatherEnabled:Boolean=false,iptvPackage:String="tv.own.owntv").
- [ ] ConfigCodec.encode(config):String and decode(text):LauncherConfig use versioned JSON, tolerant invalid-field fallback, bounded columns/dock/module counts, unknown-future-schema safe defaults. CatalogRules.deduplicate(entries):List<AppEntry>, dock(entries,pins,limit=6):List<AppEntry>, visible(entries,hidden):List<AppEntry>, movePin(pins,packageName,newIndex):List<String>, animationsEnabled(reducedMotion,lowRam):Boolean. Validate no stale/duplicate dock entries, no self launcher, stable label order, invalid module targets rejected.
- [ ] Run :app:testDebugUnitTest for red evidence before implementation, then green; write task report and commit task files only.

## Task 2 — Android runtime, remote UI and settings

- [ ] Implement app using core APIs. Files under platform/, ui/, widgets/ and MainActivity.kt; AndroidManifest.xml and res/values/ and res/drawable/.
- [ ] Full native home: clock/date, toolbar, six app dock, configurable scrollable grid, HDMI/TV inputs, OwnTV, reserved TV Hub, custom modules; high-contrast focus, short optional animations, predictable D-pad movement and accessible labels. App menu long-OK supports pin/unpin/hide; settings support dock order/slots, grid count, hidden reset, module add/remove, theme/accent, wallpaper, optional city weather, reduced motion, IPTV app selection and version/update status.
- [ ] Runtime: app discovery Leanback plus optional LAUNCHER fallback, explicit intents with errors, bounded icons and bitmap sampling off UI thread, foreground lifecycle refresh. TvInputManager enumeration, typed channel URI handoff. OwnTV default tv.own.owntv; unavailable dialog includes explicit GitHub releases link and choose-installed-app option. Reserved app.swtv.tvhub separately; no stream code.
- [ ] Weather opt-in Open-Meteo HTTPS geocoding/current temperature, city explicit, no location permission, bounded foreground refresh/caching, visible attribution/stale/error state. Do not turn opt-in on automatically.
- [ ] Theme: original native gradients and glass-like surfaces; API29 no RenderEffect. Light/dark/auto; fallback wallpaper on import errors. System settings only after explicit user tap. Update panel honestly says release feed is not configured until Phase4.
- [ ] Manifest: INTERNET for opt-in weather, Leanback and HOME entries, optional touchscreen; package query declarations for launcher discovery, OwnTV, TV Hub. No root/accessibility/remap/boot receiver/system settings write/default set or install logic. Use Android platform APIs to limit dependencies.
- [ ] Add focused tests for URL/target validation and effect policy. Build/test/lint; review errors and fix. Commit task files only and report limitations honestly.

## Task 3 — Integration, verification and delivery

- [ ] Root runs unit tests, debug build, lint; validates APK package/minSdk/permissions/signature and records hash. Add read-only emulator smoke harness if emulator support is available; record untested scenarios explicitly. Never use physical TV for UI tests in this phase.
- [ ] Independent reviewer checks spec, lifecycle/focus/memory/error/security behavior and OwnTV integration. Fix critical/important issues and repeat covering tests.
- [ ] Deliver source archive, debug APK, README/build/run instructions, reference notes, validation log and recovery/approval boundaries. Release signing/update hosting are Phase4; separate Gradle modules/formal TV Hub contract are Phase3. No physical deployment yet.
